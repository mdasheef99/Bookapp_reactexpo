## 4. Selected contracts and storage decisions

U1 local result target: {version:1, provider:'on-device'|'cloud', languageHint:'en'|'hi'|'kn'|'ml', reviewText:string, reviewOverflow:boolean, blocks?:boundedGeometry}. reviewText <=20,000 code points; retain within bound, preserve whitespace, disclose overflow. Do not label languageHint as detected language. Optional structures are validated and bounded; absence must not fail safe text. Counts for save remain separate from extraction. No arbitrary confidence score or auto page-number inference.

Cloud POST request target: {version:1, requestId:UUID, imageBase64:string, languageHint}; current consent applies to this exact prepared image and account session only. RequestId helps lineage/idempotency, is not auth, and does not persist image content. Limit decoded image to 2 MiB, encoded JSON body to 3 MiB, provider response to 1 MiB, reject invalid encoding/MIME, no remote image URLs. Response uses the same bounded review contract; no uncapped rawText duplicate. Errors: AUTH_REQUIRED, INVALID_INPUT, IMAGE_TOO_LARGE, CLOUD_DISABLED, QUOTA_EXCEEDED, PROVIDER_TIMEOUT, PROVIDER_UNAVAILABLE, NO_TEXT, INVALID_RESPONSE. Unknown details never reach reader/logs. Abort locally on close/account change and ignore late results; cancellation cannot promise to undo a provider call already sent.

Use actual user verification with the caller JWT (getUser via the established Supabase SDK is the initial compatible candidate) and server-derived user ID; a header or valid anon API-key JWT is not a signed-in user. Keep platform verification as defense in depth and verify the deployment setting before release; no change to other Edge auth. Do not log authorization or URL containing Vision key. Use current deployed-project auth evidence at U1 deployment preflight. [Supabase auth guidance](https://supabase.com/docs/guides/functions/auth).

Selected cloud quota architecture: a dedicated Library server-owned durable reservation ledger/counters, rather than per-instance memory or marketplace tables. Proposal only, no migration. Atomically claim per-user minute/day and project daily limits before provider egress, with service-only access after verified identity; client cannot reserve or override user. Unique user/request ID prevents concurrent duplicate egress. Record only ID/timestamps/state/counters, never image or text. Fixed UTC minute/day windows; initial 10/minute and 100/day/user; project daily ceiling must be configured explicitly from accepted provider budget, with a kill switch. Pending/in-flight duplicate returns conflict; do not retain OCR text as a replay cache. Terminal duplicate is reported as already processed; explicit reader retry gets a new ID. Count dispatched/uncertain requests conservatively, no refund on timeout. Atomic project/user locking and retry/terminal transitions require a separately reviewed migration/RPC plan; cleanup retains daily counts through their window. Cloud fails closed until this dependency is provisioned. Tests must prove contention and duplicate fencing; repository/provider transport must not silently retry.

Selected U3 draft adapter: existing AsyncStorage-backed interface for bounded text convenience, no encrypted-storage claim. Account/book/version keys, <=100 KiB UTF-8 JSON, <=20,000-code-point extraction, 7-day expiry, no photo/base64. Visible device-only recovery disclosure and ability to disable recovery; errors degrade to in-session retention. Native AsyncStorage is not a secure vault; web local storage is readable by same-origin scripts. Do not put 100 KiB payloads directly in SecureStore: SDK54 docs warn about native large-value rejection. Encrypted draft storage is a future separate integration, not implied by private DB RLS. [Expo SDK54 SecureStore](https://docs.expo.dev/versions/v54.0.0/sdk/securestore/).

Use the existing src/application/auth/sessionCoordinator.ts cleanup barrier; extend it with Library capture/draft/history cleanup when U3 is implemented. Clear request generations first, then serialized account-scoped persistence cleanup before exposing another session. Prevent late draft writes after logout; per-account write queue/generation tests required. Existing clearCommerceSession clears shared query/mutation caches but not future draft storage. Clear drafts on success/discard/expiry and book removal; no wholesale AsyncStorage.clear. Storage cleanup failure blocks unsafe restoration and exposes an actionable recovery state. Search/resurfacing only consume saved records, never drafts.

Schema-needs outcome: U1 local/client contracts need no business-table migration. Durable cloud quotas need a separate ledger/RPC proposal and application authority. U2 concurrency-safe overwrite may use conditional updated_at equality with insert-on-absence and conflict reread, but timestamp collision/security proof is required before adopting; a revision field/RPC would need separate migration authority. U4 initial whole-corpus search can page two owner-scoped tables with literal ILIKE escaping and deterministic per-source ordering, then merge with a bounded cursor. Test REST behavior/RLS and corpus pagination first; no new search index/RPC justified yet. U3/U5 can remain device-local. No original-image bucket is proposed.
